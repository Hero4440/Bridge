# Plan 07-02: Figma parity and real backend wiring

**Objective:** Make every production flow match the approved local `figma-make` interaction and visual hierarchy while reading and writing real Amplify data. Prototype-only values must never appear as production data.

## Rules

- `figma-make/src/App.tsx` and `figma-make/src/index.css` are the visual and interaction reference.
- Reuse the shared theme tokens and production components; do not copy simulated iOS controls or mock state.
- Every saved control needs an Amplify model write, a reload-persistence check, and loading/error/empty states.
- Activity counts, people, messages, events, badges, and journey bars must be derived from real records.

## Tasks

1. **Me and settings** — match identity, journey, badges, people, Profile, Colors, Comfort, Interests, Privacy & safety, logout, and profile deletion. Persist User/TrustedContact/photo changes and derive activity from PracticeRun, RSVP, Reflection, Message, and Contact. Automated implementation complete; visual and sandbox persistence verification pending.
2. **Home** — compare every card, empty state, greeting, event handoff, and Mo entry point with Figma; use live profile/events/activity only.
3. **Circles and DMs** — replace hardcoded circles with Group rows, match circle/chat/request screens, and provide the Figma DM-request path backed by MessageRequest/Contact/Message.
4. **Events** — match list, create, detail, RSVP, prep, reflection, and safety interactions; verify refresh persistence.
5. **Practice and Mo** — match scenario, level, feedback, pause/reset/help flows; keep Bedrock responses and persisted PracticeRun data real.
6. **Auth and onboarding** — verify one-time profile gating, name/interests/trusted person/theme/comfort saves, logout/login, and deleted-profile behavior.
7. **Parity gate** — capture phone-width screenshots for every state, exercise every control, refresh after every write, inspect console, and record pass/fail in `07-TEST-RESULTS.md`.

## Acceptance criteria

- Every reachable Figma screen has a production equivalent or an explicitly approved omission.
- Every interactive control works with keyboard and touch and has visible success/error feedback.
- All user-owned changes survive refresh and a new login through real AWS services.
- No prototype counters, names, messages, circles, events, badges, or journey data are hardcoded into production.
- Unit tests, TypeScript build, and lint exit successfully; manual phone-width parity is recorded.
