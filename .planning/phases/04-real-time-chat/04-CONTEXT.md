# Phase 4: Real-Time Chat - Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver circle (group) real-time chat on AppSync + DynamoDB — CHAT-01…CHAT-07:
- Messages persist to DynamoDB (`Message` model, already defined in Phase 1).
- Circle chat updates in real-time via **AppSync subscriptions, no polling**.
- Subscription **auto-reconnects** after disconnect, with a "reconnecting…" UI state.
- Messages are **filtered by `groupId`** with authenticated access.
- A **daily topic** displays at the top of each circle chat.
- **Starter chips** (ask a question, share a story) generate suggested messages when tapped.
- Message **history loads on open** (last 50 messages).

Builds on Phase 1's `Message` model and Phase 2's `previewReplies` endpoint. **Not in this phase:**
DMs / message requests / contact accept-decline (Phase 5), safety classification & crisis
detection on messages (Phase 5), member-only visibility Lambda (D-08, Phase 5), full
frontend loading/empty/error polish everywhere (Phase 6).
**Depends on:** Phase 1 (`Message` schema), Phase 2 (`previewReplies` Lambda for chips + topic generation).
</domain>

<decisions>
## Implementation Decisions

### D-01 Circle membership & message visibility — OPEN CIRCLES (recommended)
- Circle messages use **`allow.authenticated()`**, queried/subscribed **filtered by `groupId`** — any
  signed-in user can read and post in any circle. This matches SKILL §2.2 "just read" (circles are open),
  and is exactly what CHAT-04 asks for ("filtered by groupId with authenticated access").
- The **member-only / DM-participant server-side check (D-08)** is **deferred to Phase 5**, where it lands
  with the contact + DM participant-scoping work. The `TODO(phase-chat)` in `data/resource.ts` moves to Phase 5.

### D-02 Real-time mechanism — observeQuery (recommended)
- Use Amplify Data **`observeQuery`** for the live message list: it gives real-time sync, a local cache,
  and **automatic reconnection** out of the box (CHAT-02, CHAT-03), and FRONTEND-04 already names it.
- **Initial load capped at the last 50 messages** for the circle, ordered by timestamp (CHAT-07); newer
  messages stream in via the subscription.
- Surface the AppSync **connection state** (`ConnectionState` from `aws-amplify/api`) to drive the
  **"reconnecting…" banner** (CHAT-03) — not a mock/fake loading state.

### D-03 Daily topic — AI-GENERATED, generated once per day per circle and CACHED
- The daily topic for each circle is **generated by Bedrock Claude**, NOT a static seed.
- **Cost guard (mandatory):** generate **once per day per circle** and **cache the result in a DynamoDB
  row** (a `Topic` record keyed by `groupId` + date). The chat screen **reads the cached row**; it only
  triggers generation when today's topic for that circle does not yet exist. Never call Bedrock on every
  chat open (would blow the $50 budget + rate limits).
- This stays within the no-mock rule: the UI reads a **real DynamoDB row**, not a constant array.
- **Fallback:** if Bedrock throttles/times out when generating, store/serve a warm generic starter
  (e.g. "What's something small that went okay today?") with `fallback: true`, per the resilience rule.
- Likely reuses the shared `converseWithTool` helper + a small new prompt (research/plan decides whether
  this is a new `dailyTopic` custom query or an extension of `previewReplies`).

### D-04 Starter chips — AI-GENERATED via previewReplies (recommended)
- Tapping a starter chip ("ask a question", "share a story", "write my own") calls the **existing Phase 2
  `previewReplies` Lambda** with the circle + daily-topic context, returning suggested messages.
- Suggestions are **editable before sending** and **never auto-sent** (SKILL §2.3 / guardrails — no
  auto-send, user keeps agency). "Write my own" opens a blank composer.

### Claude's Discretion
- Whether the daily topic is a new custom query vs an extension of `previewReplies`.
- Exact `Message` create/subscribe calls, ordering/secondary-index strategy for last-50-by-group,
  optimistic send vs refetch, and the shape of the `Topic` model (new model this phase).
- Reconnect-banner debounce/UX timing.
</decisions>
