## Why This Phase Exists

Practice is THE core demo feature for Nov 6 competition — users practice conversations with AI feedback before real interactions. The backend (`practiceTurn` Lambda + Bedrock) was built in Phase 2, but the UI was missed in Phase 6's frontend integration. This phase closes that gap.

---

## What Already Exists (Don't Rebuild)

### Backend (Phase 2)
✅ **Lambda:** `app/amplify/functions/practice/handler.ts`
- `practiceTurn` custom query
- Arguments: `scenarioId`, `level` (1-3), `goal` (user-set), `message` (user's response)
- Returns: `{ partnerReply, strength, tip, fallback, crisis }`
- Uses Bedrock Claude with structured output
- Crisis detection built-in

✅ **Scenarios:** 7 scenarios defined in `prompts.ts`
- `join` — joining an ongoing group chat
- `left-on-read` — a friend left your message on read
- `cancel` — a friend cancels plans last minute
- `leave` — leaving an event early when you are tired
- `repair` — repairing things after you said something harsh
- `invite` — inviting someone to do something
- `disagree` — disagreeing kindly

✅ **Support Levels:** 3 levels (from `prompts.ts`)
- Level 1: Guided — gentle hint chips, very encouraging
- Level 2: Light help — fewer hints, only if stuck
- Level 3: On your own — no hints, realistic surprise

✅ **Safety:** Guardrails in prompts (SKILL.md §2.7)
- Judge only against user's goal, not "neurotypical"
- Crisis detection → stop + 988
- No medical/legal/financial advice
- Parity (advice doesn't change with diagnosis mention)

## Key Decisions

### 1. Where Does Practice Live?

**Decision:** Add Practice as a **6th tab** in NavBar (replacing or alongside existing tabs).

**Options considered:**
- **Option A:** Replace "Me" temporarily → NO (Me is essential for profile/signout)
- **Option B:** Add 6th tab "Practice" → YES (simple, clear)
- **Option C:** Nest under Home → NO (adds complexity)

**Rationale:** Clean separation, matches prototype where Practice is top-level.

---

### 2. Practice Flow

**Decision:** 4-step linear flow (no back/forth after starting conversation)

**Steps:**
1. **Scenario picker** — 7 cards, tap one to select
2. **Level + Goal** — 3 level buttons + text input for goal ("I want to...")
3. **Conversation** — chat-style UI, user types, AI replies with partner response
4. **Feedback** — strength + tip displayed, "Try Again" or "Done"

**Match prototype:** Yes, this matches figma-make flow exactly.

---

### 3. API Integration

**Decision:** Call `practiceTurn` query directly via Amplify Data client

**Implementation:**
```typescript
const { data, errors } = await client.queries.practiceTurn({
  scenarioId: 'join',
  level: 1,
  goal: userGoal,
  message: userMessage
});
// Returns: { partnerReply, strength, tip, fallback, crisis }
```

**No mocking:** Real Bedrock calls only. Fallback responses come from Lambda, not client-side.

---

### 4. UI Patterns (Reuse Phase 6)

**Decision:** Reuse existing patterns for consistency

- **Loading:** LoadingSpinner while waiting for AI (Bedrock can take 2-5 seconds)
- **Error:** ErrorRetry component if API fails
- **Empty:** EmptyState for "No recent practices" (if we show history)
- **Mo:** Show Mo buddy during conversation (changes mood based on user's tone)

---

### 5. Crisis Handling

**Decision:** If `crisis: true` from API, stop conversation and show 988 + trusted person

**UI Flow:**
1. User types something indicating self-harm
2. AI returns `{ crisis: true }`
3. Immediately show alert: "It sounds like you might need help. Call 988 or reach out to [trusted person name]."
4. Conversation ends, return to scenario picker

**Match backend:** Yes, Lambda already detects crisis via `classify()`.

---

### 6. Conversation History

**Decision:** **Do NOT persist practice runs** for v1 (phase constraint)

**Rationale:**
- PracticeRun model exists but persistence is complex
- Demo only needs live practice, not history
- Phase 2 comment: "NOTE: PracticeRun persistence... is deferred"

**For demo:** User can practice multiple times, but no "View past practices" screen.

---

### 7. Navigation After Practice

**Decision:** After "Done", return to scenario picker (stay in Practice tab)

**Options considered:**
- Return to Home → NO (user might want another practice)
- Stay in Practice → YES (allow immediate retry)
